# Culture Characters — Workshop Preview制作・採用手順

## 目的と適用範囲

- 対象は初回公開以降の `About/Preview.png`（RimWorldのMod一覧・Steam Workshopのメインプレビュー）。Workshop説明本文に挿入する画像やゲーム内テクスチャとは別の素材。
- **プレイヤーが一目で「古代～中世日本に合った人物の背景・特性のMod」と判断できる**ことを最優先とする。画面が示す機能は [Design](../Design.md) と実際の製品XML/C#、[README](../../README.md) を正本とする。
- 画像の制作・客観的な品質検査・必要な修正・採用後の配置は担当エージェントの作業範囲。作者に制作や画像の中継を依頼しない。**最終的な構図・画風・採否は作者の判断**とし、候補作成や手順の文書化だけで承認扱いしない。
- 本書は **Characters固有** の制作手順であり、AMJ全Modの共通カバー構図や他Modの採用済みレイアウトを制定・流用しない。[Project ArtStyle](https://github.com/sucRo-RimWorld/Ancient-Medieval-Japan-Project/blob/main/Docs/ArtStyle.md) のゲーム内Thing/Plant用256px・透明背景・MO輪郭ルールを、宣伝用Previewへ機械的に適用しない。

## 絵柄・メッセージの判断基準

1. **人物が主題**。中世日本の暮らしに存在した多様な成人・子ども、村人・職人・旅人・漁村・祭祀などの生活背景を想起できること。特定の武士・貴族・公家集団だけをコロニー全体の前提として描かない。
2. 「職業・幼少期の背景と特性を調整する」Modとして伝わる図柄を選ぶ。衣装・武器・建物・勢力・新作業・新種族・新しい画面UIなど **実装していない要素を追加するModに見せない**。イラスト上の人物服装は雰囲気表現であり、ゲーム内で追加される装備の宣伝ではないと判断できる構図にする。
3. 絵の描き方（単独人物、複数人の群像、切り絵風、イラストとタイポグラフィの組み合わせ等）は候補ごとに選べる。**特定の背景色、タイトル位置、固定枠、人物人数、タッチを必須条件にしない**。採用済みのCharacters専用Previewが将来存在すれば、その原本を比較対象にする。
4. 文字を入れる場合は Mod名または `Characters / 人物` など主題の識別に必要な最少量に抑える。日本語・英語とも小さなWorkshopサムネイルで判読できるか確認する。装飾的な疑似漢字、崩れた文字、出典不明の家紋・紋章を使わない。
5. 数字を掲示する場合は **既存背景126件の改稿** と **通常生成可能な新規背景12件（成人8・幼少4）** を混同しない。新規定義14件のうち2件は重複回避で通常生成から除外される。「126人・126背景を新規追加」「14件が通常生成可能」などと主張しない。新特性2件は酒好き／酒嫌いであり、酒造・新しい薬物製造は追加しない。数字をあえて掲載する必要はない。
6. 素材は自作・使用許諾済み原本・利用条件を検証したものに限定。他Modのプレビューやゲーム内画像、外部の人物写真、家紋などを出典・権利を確認せず転載・加工しない。既存素材を採用するときは原本と派生手順を保存する。

## 技術仕様

- 採用先パスは **`About/Preview.png`**。実際のPNG形式で書き出す。透明背景は必須ではない（通常は背景のある完成画像）。偶発的な透明領域、背景欠落、文字の欠けは不合格。
- アスペクト比 **16:9**。採用出力は原則 **640×360 px PNG**。必要があれば **1280×720 px** の高解像度を選んでよいが、いずれも **1 MiB未満（Steamの1 MB上限を安全側で満たす）**。ワーク用には高解像度原本を保存し、承認される最終版を一度だけ書き出す。
- リサイズ時は構図を引き伸ばさず、意図しない切り取り・レターボックス・可読性低下を防止する。色空間はWeb表示可能なsRGB、最終ファイルは開けるPNGとする。プレビューだけのためのDDS変換は不要。
- 参考: [RimWorld Wiki — Mod Folder Structure](https://rimworldwiki.com/wiki/Modding_Tutorials/Mod_Folder_Structure)（Preview推奨640×360、16:9、1MB未満）。**配布ZIPは作成しない**。採用したPreviewを通常のModルートの `About/` に含め、[ReleaseChecklist](../ReleaseChecklist.md) の直接アップロード手順に従う。

## 制作 → 監査 → 採用

1. **着手前照合**： `About/About.xml`、`Docs/Design.md`、`README.md`、実際の `Defs/`・`Patches/` と、既存採用画像があればその原本を確認。未実装機能や過去の候補案を絵柄の根拠にしない。
2. **候補作成**：必要なら画像生成・原本合成・人手編集を使用する。現行の原本を使った修正で済む場合はむやみに全面再生成しない。生成候補は採用済み素材とは別に管理し、無承認の上書きをしない。
3. **生成直後の監査（毎回）**：採用済みのCharacters画像／選んだ参照画像／元画像と比較し、(a) 人物の形状・服装・時代や役割の違和感、(b) 画風と情報密度、(c) 背景の欠落・不要な透過、(d) 寸法・比率・容量、(e) 輪郭の見え方、(f) 文字の正確さ・読みやすさを確認する。**各候補の採否と理由を明示**。宣伝対象を誤る候補、文字化け、視認性不足、画像破損は不採用。
4. **縮小表示の監査**：原寸だけでなく、Workshop一覧のような小さな表示サイズでも人物・タイトル・主題が識別でき、端が切れないことを確認。比率に合わないだけの余白追加ではなく、必要なら構図を調整する。
5. **作者の最終採用判断**：監査済み候補と、元画像との相違点、採用理由・残る懸念を提示する。画像生成ツールが未監査の結果を即時表示する場合は、**その表示を監査・採用済みと偽らない**。作者の採用前に `About/Preview.png` を確定・公開済みとして扱わない。
6. **原本保全・GitHub反映**：採用されたPNGの正確なバイト列と編集可能な元データ（存在する場合）を保持し、トピックブランチ→PR→必要なチェック→`main` に統合。画像が実際にGitHubに入った場合にだけ画像更新完了を報告し、実コミットSHAを示す。
7. **公開直前**：`About/Preview.png` が現行の承認済み原本と一致し、画像技術仕様とタイトル・説明内容が現行README・Workshop原稿に合うことを確認する。画像単独の承認はSteam初回公開や視認性設定の承認ではない。ライブのSteam表示・配布反映は別に確認する。

## 現在の状態
